## 2. EA概要(レビューの前提知識)

XAUUSD(XM KIWAMI口座では `GOLD#`)のM15専用。アジア時間(サーバー1〜9時)の
レンジを構築し、レンジ品質フィルタ(日足ATR比0.10〜0.60)を通った日のみ、
ロンドン〜NY前半(9〜15時)の確定足ブレイクでエントリー。H4 EMA(50)トレンド
フィルタ、追いかけ禁止(レンジ端から日足ATR×0.25超は見送り)。
SLはレンジ反対側(日足ATR×0.8キャップ)、TPは1.6R、+1RでBE移動後H1 ATR×2.5で
トレール。22時またはセッション終了15分前に強制フラット。オーバーナイトなし。

## 3. 監査で実測された4問題と修正仕様(v1.10) — 各項目の実装を検証せよ

### 3-1. オーバーナイト持ち越し(重大)

- **問題**: 祝日短縮日(実測: 2025-06-19)に22時以降のティックが来ないと強制
  フラットが発火せず、日付をまたぐと `hour >= InpFlatHour` 判定がリセットされ、
  ポジションが翌日22時まで36.75時間保持された
- **修正仕様**:
  a. `CloseStalePositions()`: `POSITION_TIME < 当日サーバー日付の0時` の自社
     ポジション(マジック・シンボル一致)を検出したら即決済。OnTickの先頭で毎回実行
  b. `SessionCloseSoon()`: `SymbolInfoSessionTrade` で当日の最終取引セッション
     終了時刻を取得し、`InpPreCloseBufferMin`(15分)前から強制フラット
  c. `OnTimer`(60秒): ティック無しでも a/b を執行
- **受け入れ基準**: 回帰テストで6/19建てのショートが**翌20日の最初のティック
  までに決済**されること。日をまたいで22時まで保持されるパスが存在しないこと

### 3-2. DDロックアウトが保有を放置

- **問題**: 資産最高値(HWM)から-10%で新規停止のみ。保有ポジション未決済
- **修正仕様**: `InpFlattenOnDDLock`(デフォルトtrue)で、ロック条件成立中は
  保有全決済。新規停止は従来どおり
- **受け入れ基準**: `DrawdownLocked()` がtrueの間、新規エントリーが不可能かつ
  (フラグon時)保有が決済されるコードパスであること

### 3-3. SL変更が高頻度(20取引で117回)

- **問題**: トレールが1ポイント刻みで変更要求を送信し、ライブでのリクエスト
  拒否・制限リスク
- **修正仕様**: SL改善幅が `InpTrailStepPoints`(30ポイント)以上のときのみ
  `PositionModify` を送信。BE移動(1回きり)は対象外
- **受け入れ基準**: 同一期間の回帰テストでSL変更回数が大幅減(目安: 50回未満)。
  ステップ未満の改善で変更要求を送るパスがないこと

### 3-4. HWMキーの口座間混入

- **問題**: GlobalVariableキーが `シンボル+マジック` のみで、同一ターミナルの
  別口座に状態が漏れる
- **修正仕様**: キーに `ACCOUNT_LOGIN` を含める
  (`GSB_HWM_<login>_<symbol>_<magic>`)
- **受け入れ基準**: キー生成に口座識別子が含まれること

## 4. v1.11 小資金フォールバック仕様 — 実装を検証せよ

- 通常時: リスク金額 = 資産 × `InpRiskPercent`%。SL距離からロット算出、
  ステップ切り捨て。**最小ロット未満なら見送り**(過大リスク拒否)が原則
- `InpAllowMinLotFallback=true` のときのみ例外: 最小ロットでの実リスク%が
  `InpHardRiskCapPct` 以下なら最小ロットでエントリー。超えるなら見送り+ログ
- **受け入れ基準**: フォールバック経由でも1トレードの実リスクが
  `InpHardRiskCapPct` を超えるパスが存在しないこと。デフォルト(false)では
  v1.10と同一挙動であること

## 5. 不変条件(これらに反する箇所があれば重大指摘)

1. エントリーロジック(レンジ構築・品質フィルタ・ブレイク判定・トレンド
   フィルタ)はv1.00から不変であること
2. すべての新規注文はSL/TP付きで発注されること。SLを外すパスがないこと
3. 1トレードの計画リスクが `max(InpRiskPercent, InpHardRiskCapPct)` を
   超えるパスがないこと
4. データ取得失敗時はフェイルクローズ(取引しない)であること。
   例外はニュースカレンダー取得失敗のみ(フェイルオープン+一度だけログ)
5. DLL・外部通信・ファイル書き込みを使用しないこと
6. ポジション操作は必ずマジックナンバー+シンボルでフィルタされていること

## 6. レビュー観点チェックリスト(MQL5固有)

- `CopyBuffer`/`CopyRates` の戻り値チェック漏れ、配列範囲外
- `SYMBOL_TRADE_TICK_SIZE`/`TICK_VALUE` の扱い(円口座での通貨整合を含む)
- `NormalizeDouble` と `SYMBOL_VOLUME_STEP` の丸め、`SYMBOL_TRADE_STOPS_LEVEL`
  違反の可能性(BE移動・トレール・発注時)
- フィリングモード選択(`SYMBOL_FILLING_MODE` フラグ判定)の妥当性
- 日またぎ・週明け・祝日短縮・サーバー時刻(GMTオフセット)の境界条件
- `OnTick` と `OnTimer` の同時実行を想定した状態変数の整合
- ログスパム(閉場中のリトライ等)、無限ループの可能性
- `HistorySelect` ベースの当日エントリー数カウントの正確性

## 7. 回帰テスト仕様(実行環境がある場合)

GOLD#(KIWAMI)の履歴が利用できない環境では、以下の段階的プロトコルで実行する。

### 7-A. 代理回帰(標準口座 GOLD) — v1.10修正の検証

v1.00監査ベースラインとの比較試験。**コード以外の条件をv1.00監査と完全に
一致させること。KIWAMIプリセットは使用禁止**(スプレッドゲート25が標準
スプレッドでエントリーを弾き、リスク1%+フォールバックが見送りパターンを
変えるため、比較が全て壊れる):

- 環境: 標準口座の `GOLD`、M15、リアルティック、初期資金 $10,000、
  **全パラメータはデフォルトのまま**
- 期間: 2025-05-01〜2025-08-09
- 測定項目: ①6/19持ち越しの解消 ②エントリー一致 ③SL変更回数
- 期待される差分(これらは合格側。回帰として報告しないこと):
  (a) 2025-06-19建てのショートが翌20日の最初のティックまでに決済される
  (b) **6/20に新規エントリーが増える可能性がある** — v1.00では持ち越し
      ポジションが同方向の新規をブロックしていたため。回帰ではない
  (c) トレールのステップ化による決済価格の差
  (d) (a)〜(c)以降の資産経路の分岐に起因するロットサイズの微差
  (e) v1.12以降: ロット計算にスリッページ加算が入ったため、v1.00比で
      ロットが1ステップ小さくなる、または境界日にエントリーが見送りに
      変わる差分(小資金時)が発生し得る
- 上記以外のエントリー時刻・方向の差分はすべて報告対象

### 7-B. 円建てロット挙動の煙試験(任意)

- 環境: 7-Aと同じ標準 `GOLD`、初期資金 150,000 JPY、KIWAMIプリセット適用、
  ただし `InpMaxSpreadPoints=45` に戻す(標準スプレッド用)
- 目的: 小資金でのフォールバック発動・見送り・実リスク上限の挙動確認
- 確認: フォールバックのログに出る実リスク%が常に `InpHardRiskCapPct` 以下で
  あること。スプレッド条件が異なるためKIWAMI合格の代用にはならない

### 7-C. KIWAMI本検証(GOLD#履歴が利用可能になり次第)

- 環境: KIWAMI口座のMT5、`GOLD#`、初期資金 150,000 JPY、プリセット適用
- 7-A/7-Bの合格は**本項の代用にならない**。プリセット(特にスプレッド
  ゲート25)の最終判定は本項でのみ行う

合格基準(全段階共通): コンパイル 0 errors / 0 warnings、
3-1〜3-4の受け入れ基準充足

## 8. 報告フォーマット

指摘は以下の形式で。仕様違反ではない改善アイデアは「提案」として分離し、
実装はしないこと。

```
[重大度: Critical/Major/Minor] ファイル:行
事象: 何が起きるか
根拠: 本指示書の仕様番号(例: 3-1, 5-3)
再現条件: どの入力・相場状況で発生するか
パッチ案: 最小差分(diff形式)
```

指摘ゼロの場合も「各仕様番号に対する確認結果」を一覧で報告すること。
