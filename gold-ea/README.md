# GoldSessionBreakout — XAUUSD ロンドンブレイクアウトEA

XAUUSD(ゴールド)専用のMQL5 EA。**利益を保証するものではありません。**
このEAは「勝てるロジック」を売り物にするのではなく、EAが死ぬ典型的な原因
(コスト無視・リスク管理欠如・過剰適合)を構造的に潰すことを設計の中心に置いています。

## 設計思想

エッジの源泉を「インジケーターの組み合わせ」ではなく「市場構造」に置く。

ゴールドの1日には明確な流動性サイクルがある:

- **アジア時間**: 参加者が少なくボラティリティが収縮、レンジを形成する
- **ロンドン〜NY時間**: 欧米勢の参入でボラティリティが拡張し、方向が出る

このEAはアジアレンジの確定後、ロンドン〜NY前半のブレイクアウトだけを取りにいく。
インジの閾値の微妙な組み合わせに依存しないため、パラメータ感度が低く
過剰適合しにくいのが狙い。

「そのレンジをブレイクしたら乗る」だけでは勝てないので、以下のフィルタで
質の悪い日を捨てる:

1. **レンジ品質フィルタ**: アジアレンジ幅が日足ATR比で狭すぎる日(ノイズで
   すぐ抜ける)と広すぎる日(既にトレンド発生済み・指標日)は取引しない
2. **H4トレンドフィルタ**: EMA(50)に対する終値の位置と同方向のブレイクのみ
3. **追いかけ禁止**: ブレイク確認時に価格がレンジ端から走りすぎていたら見送り
   (成行で高値掴みしない)
4. **確定足ベースのブレイク判定**: ヒゲの一瞬の抜けでは入らない

## モジュール構成

```
┌─────────────────────────────────────────────┐
│ OnTick                                      │
│  ├─ Day/State manager   日次リセット・状態管理  │
│  ├─ Range builder       アジアレンジ構築+品質判定│
│  ├─ Signal engine       確定足ブレイク+トレンド │
│  ├─ Execution guards    スプレッド/ニュース/時間 │
│  ├─ Risk manager        ロット計算/日次停止/DDロック│
│  └─ Trade manager       BE移動/ATRトレール/強制フラット│
└─────────────────────────────────────────────┘
```

## リスク管理(このEAの本体)

| 機構 | 内容 | デフォルト |
|---|---|---|
| 固定フラクショナル | 1トレードの損失を口座資産の一定%に固定 | 0.5% |
| SL | レンジ反対側(日足ATR×0.8でキャップ) | — |
| TP | リスクリワード固定 | 1.6R |
| ブレイクイーブン | +1Rで建値+スプレッド分へSL移動 | 1.0R |
| トレーリング | BE後、H1 ATR×2.5で追従 | 2.5 |
| 日次損失ストップ | 日初資産から-2%で当日の新規停止+全決済 | 2% |
| DDロックアウト | 資産最高値から-10%で完全停止(手動リセットまで) | 10% |
| 強制フラット | ロールオーバー前に全決済。オーバーナイトなし | 22時(サーバー) |
| スプレッドガード | 上限超過時はエントリーしない | 45ポイント |
| ニュースフィルタ | 米国高重要度指標の前後30分は新規停止(MQL5経済カレンダー) | on |

ロット計算は「最小ロットでもリスク上限を超える場合はエントリーしない」
(小さすぎる口座で過大リスクを取らない)。証拠金不足時も自動減量。

## 導入

1. `GoldSessionBreakout.mq5` を `MQL5/Experts/` に置き、MetaEditorでコンパイル
2. **XAUUSD の M15 チャート**にアタッチ
3. **セッション時刻はサーバー時間**。デフォルトはGMT+2/+3(EET)ブローカー想定
   (アジア=1〜9時、エントリー〜15時、フラット=22時)。ブローカーのタイムゾーンが
   違う場合は必ず補正すること
4. ニュースフィルタはライブ/デモで動作。古いビルドのストラテジーテスターでは
   カレンダーが取れないため自動的に無効化される(ログに1回表示)

## 検証プロセス(ここを飛ばすと全てが無意味)

「今までのEAが全く効かなかった」原因は、ほぼ確実にこの工程の欠如です。
以下を順番に、**全部**やってください。

1. **実ティック+実スプレッドでバックテスト**
   「全ティック(リアルティック)」モード必須。「始値のみ」のゴールドEAテストは無意味。
   スリッページも加味する(ゴールドは平均2〜5ポイント滑る前提)
2. **イン/アウトオブサンプル分割**
   例: 2015–2022でパラメータを決め、2023–現在には**一切触らずに**検証。
   OOSで崩れるならその時点で捨てる
3. **ウォークフォワード分析**
   1年最適化→次の6ヶ月検証、を窓をずらして繰り返す。全窓の検証区間を
   つなげた成績が本当の期待値に近い
4. **パラメータは「山」ではなく「台地」を選ぶ**
   最適値の±20〜30%動かしても成績が緩やかにしか劣化しない領域を採用する。
   1点だけ突出して良いパラメータは過剰適合のサイン
5. **モンテカルロ検証**
   トレード順序をシャッフルして最大DDの分布を見る。95パーセンタイルDDが
   自分の許容(このEAなら10%ロックアウト)を超えるならリスク%を下げる
6. **デモ/最小ロットで3ヶ月フォワード**
   バックテストとフォワードの乖離(スプレッド・滑り・約定拒否)を実測する
7. **ライブは最小リスクから**
   0.25%リスクで開始し、100トレード程度の実績が想定分布内に収まってから
   0.5%へ

## 期待値について正直に

- 「AIが1発で作った儲かるEA」の話は、バックテスト曲線の見せ合いか生存者バイアスです。
  検証工程を経ていない損益曲線に情報価値はありません
- このEAの狙いは「絶対勝つ」ではなく、**正の期待値が出うる構造的仮説 + 破産しない
  リスク管理 + 期待値が消えたことを検知できる運用**の3点セットです
- ブレイクアウト型は勝率40〜50%・損益レシオで稼ぐタイプ。連敗は正常動作です。
  日次-2%/DD-10%のガードはそのためにあります
- 相場のレジームが変われば期待値は消えます。月次でウォークフォワードを回し、
  OOS成績がモンテカルロの想定分布から外れたら止める、を運用ルールに組み込むこと

## パラメータ早見

| グループ | 主要パラメータ | 意味 |
|---|---|---|
| Sessions | `InpAsiaStartHour/EndHour` | アジアレンジの定義(サーバー時間) |
| Range | `InpMinRangeATR/MaxRangeATR` | レンジ品質(日足ATR比) |
| Range | `InpBreakBufferATR` | ブレイク判定バッファ |
| Trend | `InpUseTrendFilter/TrendTF/TrendMAPeriod` | 上位足トレンドフィルタ |
| Risk | `InpRiskPercent/TPRR/DailyLossPct/MaxDrawdownPct` | リスク管理一式 |
| Guards | `InpMaxSpreadPoints/UseNewsFilter` | 執行ガード |

補足: ゴールドは長期の上方ドリフトがあるため、`InpAllowShort=false` の
ロングオンリー版も比較検証する価値があります。
