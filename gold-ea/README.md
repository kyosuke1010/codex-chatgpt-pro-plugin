# GoldSessionBreakout — XAUUSD ロンドンブレイクアウトEA

XAUUSD(ゴールド)専用のMQL5 EA。**利益を保証するものではありません。**
このEAは「勝てるロジック」を売り物にするのではなく、EAが死ぬ典型的な原因
(コスト無視・リスク管理欠如・過剰適合)を構造的に潰すことを設計の中心に置いています。

## 設計思想

エッジの源泉を「インジケーターの組み合わせ」ではなく「市場構造」に置く。

ゴールドの1日には明確な流動性サイクルがある:

- **アジア時間**: 参加者が少なくボラティリティが収縮、レンジを形成する
- **ロンドン〜NY時間**: 欧米勢の参入でボラティリティが拡張し、方向が出る

このEAはアジアレンジの確定後、ロンドン〜NY前半のブレイクアウトだけを取りにいく。
インジの閾値の微妙な組み合わせに依存しないため、パラメータ感度が低く
過剰適合しにくいのが狙い。

「そのレンジをブレイクしたら乗る」だけでは勝てないので、以下のフィルタで
質の悪い日を捨てる:

1. **レンジ品質フィルタ**: アジアレンジ幅が日足ATR比で狭すぎる日(ノイズで
   すぐ抜ける)と広すぎる日(既にトレンド発生済み・指標日)は取引しない
2. **H4トレンドフィルタ**: EMA(50)に対する終値の位置と同方向のブレイクのみ
3. **追いかけ禁止**: ブレイク確認時に価格がレンジ端から走りすぎていたら見送り
   (成行で高値掴みしない)
4. **確定足ベースのブレイク判定**: ヒゲの一瞬の抜けでは入らない

## モジュール構成

```
┌─────────────────────────────────────────────┐
│ OnTick                                      │
│  ├─ Day/State manager   日次リセット・状態管理  │
│  ├─ Range builder       アジアレンジ構築+品質判定│
│  ├─ Signal engine       確定足ブレイク+トレンド │
│  ├─ Execution guards    スプレッド/ニュース/時間 │
│  ├─ Risk manager        ロット計算/日次停止/DDロック│
│  └─ Trade manager       BE移動/ATRトレール/強制フラット│
└─────────────────────────────────────────────┘
```

## リスク管理(このEAの本体)

| 機構 | 内容 | デフォルト |
|---|---|---|
| 固定フラクショナル | 1トレードの損失を口座資産の一定%に固定 | 0.5% |
| SL | レンジ反対側(日足ATR×0.8でキャップ) | — |
| TP | リスクリワード固定 | 1.6R |
| ブレイクイーブン | +1Rで建値+スプレッド分へSL移動 | 1.0R |
| トレーリング | BE後、H1 ATR×2.5で追従。SL変更は最小改善幅(30ポイント)以上のときのみ送信 | 2.5 / 30pt |
| 日次損失ストップ | 日初資産から-2%で当日の新規停止+全決済 | 2% |
| DDロックアウト | 資産最高値から-10%で新規完全停止+保有全決済(手動リセットまで) | 10% |
| 強制フラット | 22時+セッション終了15分前の早い方で全決済。前日建てポジションの持ち越しを検出したら次のティックで即決済。ティックが来なくてもタイマー(60秒)で執行 | 22時(サーバー) |
| スプレッドガード | 上限超過時はエントリーしない | 45ポイント |
| ニュースフィルタ | 米国高重要度指標の前後30分は新規停止(MQL5経済カレンダー) | on |

ロット計算は「最小ロットでもリスク上限を超える場合はエントリーしない」
(小さすぎる口座で過大リスクを取らない)。証拠金不足時も自動減量。

## 導入

1. `GoldSessionBreakout.mq5` を `MQL5/Experts/` に置き、MetaEditorでコンパイル
2. **XAUUSD の M15 チャート**にアタッチ
3. **セッション時刻はサーバー時間**。デフォルトはGMT+2/+3(EET)ブローカー想定
   (アジア=1〜9時、エントリー〜15時、フラット=22時)。ブローカーのタイムゾーンが
   違う場合は必ず補正すること
4. ニュースフィルタはライブ/デモで動作。古いビルドのストラテジーテスターでは
   カレンダーが取れないため自動的に無効化される(ログに1回表示)

## 必要資金について

EAは口座残高から自動でロットを計算するため、特定の初期資金は要件ではない。
ただし**最小ロット(0.01)が実質的な下限**を作る。XM標準口座のGOLDは
1ロット=100oz、つまり0.01ロット=1ozで、SL幅$1につきリスク$1。
このEAのSL幅は日足ATR依存で概ね$5〜30のため:

| 資金 | リスク0.5%の許容損失 | 挙動 |
|---|---|---|
| $10,000〜 | $50〜 | ほぼ全シグナルを取引(0.02ロット〜) |
| $3,000前後 | $15 | レンジの狭い日のみ0.01ロットで取引 |
| $1,000以下 | $5 | ほぼ全シグナルを見送り(過大リスク拒否) |

小資金で動かす選択肢(上から推奨順):

1. **リスク%を上げる**: `InpRiskPercent=1.0` なら必要資金は半分。
   1日最大2トレード(ロング1+ショート1)なので日次-2%ストップと整合する上限
2. **最小ロットフォールバック**: `InpAllowMinLotFallback=true` にすると、
   目標リスクに収まらなくても実リスクが `InpHardRiskCapPct`(デフォルト2%)以下なら
   0.01ロットでエントリーする。**注意: この場合1敗で日次ストップに達しうる。**
   リスクが資金に対して固定されない=固定フラクショナルの複利性が失われる点も理解の上で
3. **マイクロ/セント系口座**: コントラクトサイズが小さい口座タイプなら
   下限問題自体が消える(ブローカーのGOLD仕様を要確認。コードは
   ティックバリューを口座から取得するので自動対応する)

いずれにせよ検証(バックテスト)は運用予定の資金額・口座タイプで回すこと。
$10,000でのテスト結果は$1,000運用の挙動を代表しない。

### プリセット: XM KIWAMI / 資金15万円

`presets/KIWAMI-150k-JPY.set` に設定済み(テスターの「パラメーター読み込み」から適用。
読み込めない場合は下表を手入力)。ベースからの変更点:

| パラメータ | 値 | 理由 |
|---|---|---|
| `InpRiskPercent` | 1.0 | 0.5%(¥750≈$4.6)では対応できるSL幅が狭すぎ、ほぼ全シグナルが見送りになる |
| `InpAllowMinLotFallback` | true | SL幅$9〜18の日を0.01ロットで拾う |
| `InpHardRiskCapPct` | 2.0 | 実リスク上限¥3,000≈$18.5。それ以上のSL幅の日は見送り |
| `InpMaxSpreadPoints` | 25 | KIWAMIの狭スプレッド基準(平常時の1.5〜2倍が目安) |

ドル換算はUSDJPY=162円時点。円建て口座のためSL幅$1あたりの円リスクは
為替で変動する(円安ほど取引可能な日が減る)が、EAはティックバリューから
毎トレード再計算するので設定変更は不要。

この資金規模での注意:
- 1敗最大¥3,000・日次ストップ2%(¥3,000)のため、最悪1敗で当日終了する。正常動作
- 資金が24〜33万円程度(162円時点の目安)に育つまでは実質「常に0.01ロット」で、
  固定フラクショナルの複利性は効かない。そこまでは金額を稼ぐフェーズではなく
  **検証プロセスを完走させるフェーズ**と割り切ること
- バックテストは初期資金150,000 JPY・KIWAMIサーバー・`GOLD#`・リアルティックで回すこと

## 検証プロセス(ここを飛ばすと全てが無意味)

「今までのEAが全く効かなかった」原因は、ほぼ確実にこの工程の欠如です。
以下を順番に、**全部**やってください。

1. **実ティック+実スプレッドでバックテスト**
   「全ティック(リアルティック)」モード必須。「始値のみ」のゴールドEAテストは無意味。
   スリッページも加味する(ゴールドは平均2〜5ポイント滑る前提)
2. **イン/アウトオブサンプル分割**
   例: 2015–2022でパラメータを決め、2023–現在には**一切触らずに**検証。
   OOSで崩れるならその時点で捨てる
3. **ウォークフォワード分析**
   1年最適化→次の6ヶ月検証、を窓をずらして繰り返す。全窓の検証区間を
   つなげた成績が本当の期待値に近い
4. **パラメータは「山」ではなく「台地」を選ぶ**
   最適値の±20〜30%動かしても成績が緩やかにしか劣化しない領域を採用する。
   1点だけ突出して良いパラメータは過剰適合のサイン
5. **モンテカルロ検証**
   トレード順序をシャッフルして最大DDの分布を見る。95パーセンタイルDDが
   自分の許容(このEAなら10%ロックアウト)を超えるならリスク%を下げる
6. **デモ/最小ロットで3ヶ月フォワード**
   バックテストとフォワードの乖離(スプレッド・滑り・約定拒否)を実測する
7. **ライブは最小リスクから**
   0.25%リスクで開始し、100トレード程度の実績が想定分布内に収まってから
   0.5%へ

## 期待値について正直に

- 「AIが1発で作った儲かるEA」の話は、バックテスト曲線の見せ合いか生存者バイアスです。
  検証工程を経ていない損益曲線に情報価値はありません
- このEAの狙いは「絶対勝つ」ではなく、**正の期待値が出うる構造的仮説 + 破産しない
  リスク管理 + 期待値が消えたことを検知できる運用**の3点セットです
- ブレイクアウト型は勝率40〜50%・損益レシオで稼ぐタイプ。連敗は正常動作です。
  日次-2%/DD-10%のガードはそのためにあります
- 相場のレジームが変われば期待値は消えます。月次でウォークフォワードを回し、
  OOS成績がモンテカルロの想定分布から外れたら止める、を運用ルールに組み込むこと

## パラメータ早見

| グループ | 主要パラメータ | 意味 |
|---|---|---|
| Sessions | `InpAsiaStartHour/EndHour` | アジアレンジの定義(サーバー時間) |
| Range | `InpMinRangeATR/MaxRangeATR` | レンジ品質(日足ATR比) |
| Range | `InpBreakBufferATR` | ブレイク判定バッファ |
| Trend | `InpUseTrendFilter/TrendTF/TrendMAPeriod` | 上位足トレンドフィルタ |
| Risk | `InpRiskPercent/TPRR/DailyLossPct/MaxDrawdownPct` | リスク管理一式 |
| Risk | `InpFlattenOnDDLock` | DDロックアウト時に保有も全決済 |
| Risk | `InpAllowMinLotFallback/HardRiskCapPct` | 小資金向け最小ロット許可と実リスク上限 |
| Risk | `InpTrailStepPoints` | トレールSL変更の最小改善幅(ポイント) |
| Sessions | `InpPreCloseBufferMin` | セッション終了何分前にフラットするか |
| Guards | `InpMaxSpreadPoints/UseNewsFilter` | 執行ガード |

補足: ゴールドは長期の上方ドリフトがあるため、`InpAllowShort=false` の
ロングオンリー版も比較検証する価値があります。

## 更新履歴

### v1.13 — v1.12回帰で実測されたバックオフ起因の決済遅延の修正

- v1.12の15秒バックオフが開場をまたぐと、持ち越しポジションの決済が
  最初の取引可能ティックから最大15秒遅れる(実測8秒)ことが判明。
  取引セッションの閉→開遷移を検知した最初のティックでバックオフを解除し、
  「最初の取引可能ティックで決済」を回復。開場後の失敗には従来どおり
  15秒バックオフを適用(受け入れ基準は緩和しない)

### v1.12 — 外部AIレビュー(v1.11静的監査)の指摘対応

1. **閉場中の決済リトライ暴走(Major)**: 前日ポジションの決済が閉場中に毎ティック
   再試行され、実測2秒で202回拒否された。失敗時は15秒バックオフに変更
2. **セッション情報取得失敗がフェイルオープン(Major)**: `SymbolInfoSessionTrade`
   が取得不能のとき通常取引を継続していた。フェイルクローズ(フラットモード+
   警告1回ログ)に変更。取引セッションの無い曜日も安全側に倒れる
3. **証拠金計算の2重欠陥(Major)**: `OrderCalcMargin` 失敗時に未検証ロットを
   返却+Sellでも常にBuy・Ask価格で計算していた。失敗時は見送り、
   実際の注文方向と対応する価格で計算するよう変更
4. **スリッページ経由のリスク超過(Major)**: リスク計算が発注前価格ベースで、
   不利方向へ最大50ポイント滑ると実リスクが目標/ハードキャップを超え得た。
   ロット計算のSL距離に許容スリッページを加算。**全トレードのロットが
   わずかに保守化されるため、今後の回帰テストでロットが1ステップ小さくなる
   差分は正常**
5. **EventSetTimerの戻り値未確認(Minor)**: 失敗時に警告ログを出す。ティック駆動の
   執行(第1防衛線)は維持されるため起動は継続する設計判断

### v1.11 — 小資金運用オプション

- `InpAllowMinLotFallback`(デフォルトfalse): 目標リスク%に収まらない場合でも、
  実リスクが `InpHardRiskCapPct` 以下なら最小ロットでエントリーを許可。
  従来どおりの安全側挙動(見送り)がデフォルトのまま。
  「必要資金について」の節を参照

### v1.10 — バックテスト監査(2025-05〜08, リアルティック)で実測された4問題の修正

1. **オーバーナイト持ち越し(重大)**: 祝日短縮取引日に22時以降のティックが来ないと
   強制フラットが発火せず、日付をまたぐと `hour >= 22` 判定もリセットされるため
   翌日22時まで保持される構造だった(実測: 36.75時間保持)。修正:
   前日建てポジションを検出し次のティックで即決済する `CloseStalePositions` を追加、
   シンボルのセッションスケジュールから閉場15分前を検知する `SessionCloseSoon` を追加、
   ティック無しでも執行するため `OnTimer`(60秒)を追加
2. **DDロックアウトが保有を放置**: 新規停止のみで保有ポジションを決済していなかった。
   `InpFlattenOnDDLock`(デフォルトtrue)で発動時に全決済
3. **SL変更が高頻度(20取引で117回)**: トレールが1ポイント刻みで変更要求を送っていた。
   最小改善幅 `InpTrailStepPoints`(デフォルト30ポイント)未満の変更は送信しない
4. **HWMキーの口座混入**: GlobalVariableキーに `ACCOUNT_LOGIN` を追加し口座ごとに分離。
   キー形式の変更により既存のHWM値は初回起動時に一度リセットされる

**回帰テストの見方**: 同一期間を再実行した場合、エントリーは原則v1.00と一致するはず
(エントリーロジックは未変更)。イグジットは (a) 持ち越しが発生していた日、
(b) トレールのステップ化で決済価格が変わるトレード、の2種類だけ差分が出るのが正常。
それ以外の差分が出たら報告してください。

**残存リスク(修正不能な部分)**: ブローカーが事前告知なく早期クローズした場合、
閉場前のフラットは間に合わない。その場合も翌営業日の最初のティックで即決済されるため、
持ち越しは「翌日22時まで」から「次の寄り付きまで」に短縮されるが、ギャップリスクは
ゼロにはならない。祝日カレンダーを見て手動でポジションを持たない日を作るのが確実。
