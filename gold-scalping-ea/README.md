# GoldScalperPro — XAUUSD スキャルピングEA 設計書

MT5 (MQL5) 用のゴールド専用スキャルピングEA。M1 平均回帰を中核に、
「撃たない条件」を多層フィルタで管理する構成。

---

## 0. 最初に正直な前提

- **どんなEAも利益を保証できない。** 「AIに頼んだら1発で勝てるEAができた」という話は検証不能であり、そのまま信じるべきではない。
- 勝てるEAとは「聖杯ロジック」ではなく、**エッジ仮説が明確で、検証プロセスに耐え、破産しない資金管理を持つEA**のこと。本書はその作り方を仕様化したもの。
- 本EAは**リアルティック+変動スプレッドでのバックテスト → デモでのフォワード → 最小ロットでの実弾検証**を通過するまで、利益が出るとは言えない。手順は §6 に定義。

## 1. 設計思想 — なぜ今までのEAが勝てなかったか

リテールのゴールドEAが死ぬ理由はほぼ次の4つで、エントリーロジックの優劣ではない:

| 死因 | 対策(本EAの実装) |
|---|---|
| スプレッド・滑りがスキャルの利幅を食う | スプレッド上限フィルタ、指標時刻ブラックアウト、流動性の高いセッションのみ稼働 |
| ボラティリティレジーム無視(閑散時のダマシ、暴走時の踏み上げ) | M1 ATR を下限・上限でバンド判定。「死んだ相場」と「壊れた相場」の両方で停止 |
| 資金管理の欠如(ナンピン・マーチン・SLなし) | 全ポジションに必ずハードSL。固定フラクショナル(残高比%)。ナンピンなし、同時1ポジのみ |
| 過剰最適化(カーブフィッティング) | パラメータを少なく保ち、ウォークフォワードを検証手順に組み込む(§6) |

**エッジ仮説**: ゴールドの M1 は流動性の高い時間帯において、短期の行き過ぎ
(ボリンジャーバンド逸脱 + 短期RSI極値)後に平均(ミッドバンド)へ回帰する
統計的傾向がある。エッジは小さいので、条件が揃った時だけ撃ち、
揃わない時間は一切触らないことで期待値を守る。

## 2. アーキテクチャ

単一 `.mq5` ファイル内をモジュール境界で分離(コンパイルの容易さ優先):

```
OnTick
 ├─ ExitManager   … 毎ティック: ブレークイーブン移動 / タイムストップ
 └─ 新規M1バー確定時のみ:
     ├─ RegimeGate   … 稼働可否の総合判定(§3)
     ├─ SignalEngine … 平均回帰シグナル生成(§4)
     └─ RiskManager  … ロット計算 → 発注(§5)

OnTradeTransaction … 決済結果を監視し、連敗クールダウン / 日次損失ガードを更新
```

判定はすべて**確定バー(shift=1)**の値で行い、ティック内での再描画・
先読みバイアスを排除する。エントリーは次バー寄付の成行。

## 3. RegimeGate — 「撃たない」条件(すべて AND)

1. **スプレッド** ≤ `MaxSpreadPoints`(デフォルト 35 point = $0.35)
2. **セッション**: サーバー時刻で2枠(デフォルトはGMT+2/+3ブローカー想定でロンドン午前 10:00–13:00、NY序盤〜オーバーラップ 15:30–19:00)
3. **ブラックアウト時刻**: `"HH:MM-HH:MM,..."` 形式の入力をパースし、指標発表(FOMC・雇用統計・CPI等)前後は停止。**手動管理が前提**(カレンダーAPIはテスターで再現性がないため採用しない)
4. **ボラティリティレジーム**: M1 ATR(14) が `[MinAtrPoints, MaxAtrPoints]` 内
5. **金曜カットオフ**: `FridayLastHour` 以降は新規なし
6. **日次損失ガード**: 当日開始エクイティから `DailyLossLimitPct`% 減で当日停止
7. **連敗クールダウン**: `MaxConsecLosses` 連敗で `CooldownMinutes` 停止
8. **日次トレード上限** / **同時1ポジ・1シグナルバー1回**

## 4. SignalEngine — M1 平均回帰

ロング(ショートは対称):

- 確定バーの終値 < ボリンジャーバンド(20, 2.0σ) 下限
- RSI(3) < `RsiOversold`(デフォルト 15)
- ミッドバンドからの乖離 ≥ `MinStretchAtr` × ATR(14) … 「十分に伸び切った」ことの確認
- オプション `TrendFilterMode`: M5 EMA(200) の上でロングのみ許可(押し目回帰型)/ フィルタなし / 逆張り専用

### 4.1 エントリー確認(戻り確認) — `EntryConfirm`

極値バーだけを根拠に入ると「落ちてくるナイフ」を掴む。上記条件が揃ったバーは
まず**セットアップとして待機(アーム)**し、相場が実際に戻り始めたことを
確認してから入るかを選択できる:

| モード | 挙動 | トレードオフ |
|---|---|---|
| `CONFIRM_NONE` | 極値バー確定 → 次バー寄付で即エントリー | 約定数が多く平均取得価格は有利だが、続落を直撃しやすい |
| `CONFIRM_REENTRY`(デフォルト) | 確定バーの終値がバンド内へ**戻って引けた**ことを確認してからエントリー | 勝率が上がる代わりに、価格は戻った分だけ不利になり機会も減る |
| `CONFIRM_REVERSAL_BAR` | バンド内回帰に加えバー自体が反転方向(ロングなら陽線)であることを要求 | 最も厳格。ダマシは減るが機会は最少 |

待機中のルール: `ConfirmTimeoutBars`(デフォルト5本)以内に確認が取れなければ
セットアップ破棄。待機中に同方向の極値が再出現したらタイマーをリセット、
逆方向の極値が出たらセットアップを反転。**確認成立時にレジームゲートを
再判定**し、スプレッド急拡大やセッション終了などで条件が崩れていれば見送る。

どのモードが優位かは検証で決めるべき項目(§6 の IS/OOS で3モードを比較する)。

## 5. リスク・エグジット仕様

| 項目 | 仕様 | デフォルト |
|---|---|---|
| 1トレードリスク | 残高比の固定% → SL距離からロット逆算 | 0.3% |
| SL | エントリー ∓ ATR(14) × `SlAtrMult`(必ず設定。設定不能なら発注しない) | 1.5 |
| TP | リスクリワード固定 `TpRR` × SL距離 | 1.2R |
| ブレークイーブン | +`BeTriggerRR`R 到達で SL を建値+バッファへ | 0.7R |
| タイムストップ | `MaxHoldMinutes` 経過で成行決済(回帰しないスキャルは負けの前兆) | 20分 |
| ナンピン / マーチン / グリッド | **実装しない**(禁止事項) | — |

## 6. 検証プロトコル(これを通らなければ稼働しない)

1. **データ**: MT5 ストラテジーテスターで「全ティック(リアルティック)」+ 実スプレッド。最低2年、できれば2020年以降全部。
2. **In-Sample / Out-of-Sample**: 期間を 70/30 に分割し、最適化は IS のみ。OOS で PF > 1.15、最大DD < 日次ガードと整合することを確認。
3. **ウォークフォワード**: 6ヶ月最適化 → 2ヶ月検証を転がす。全窓の合算が右肩上がりでなければ棄却。
4. **ストレス**: スプレッド +50%、約定遅延 1〜3 ティックを加えても期待値が正か。**スキャルEAはここでほぼ全滅する。生き残った設定だけが本物。**
5. **フォワード**: デモ1〜2ヶ月 → 最小ロット実弾1ヶ月。バックテストとの乖離(特に平均スプレッドコスト)を記録。
6. **稼働後**: 月次でエッジ検診。OOS期待値の半分を2ヶ月連続で下回ったら停止して再検証。

## 7. パラメータ一覧(過剰最適化防止のため最適化対象は★のみ推奨)

- ★ `RsiOversold` / `RsiOverbought`, `MinStretchAtr`, `SlAtrMult`, `TpRR`
- 固定推奨: セッション時刻、スプレッド上限、リスク%、日次ガード、タイムストップ

## 8. 拡張ロードマップ(検証通過後のみ)

1. NYオープンのモメンタム・ブレイクアウト戦略を別マジックナンバーで追加(平均回帰と負の相関を狙うポートフォリオ化)
2. ティックボリュームによる流動性フィルタ
3. 部分利確(1Rで半分、残りをミッドバンドまで)
